## Targets

- **Android first.** Reference device: Samsung Galaxy S24 Ultra. Must work on **any phone that supports the ARCore Depth API**; show the "unsupported device" screen otherwise.
- **iPhone second, from the same repo.** The project is **Kotlin Multiplatform (KMP) from day one**: scanning logic, exporters, data and settings are written once in a `shared` module; the mesh reconstruction is a shared C++ core; only AR, camera, rendering, haptics, OS integration and (for now) UI are per-platform. See `docs/07-multiplatform.md`.
- Design tokens in `design/tokens/tokens.json` are the shared source for both platforms.
- Release quality: this will go on the Play Store and later the App Store.
- Development happens in VS Code with Claude Code on an Apple Silicon Mac. Android builds via Gradle; iOS builds via Xcode tools (`xcodebuild`), with the Xcode project generated by XcodeGen so it's never hand-edited.

## Stack (recommended; flag it if you think something else is clearly better)

- **Kotlin Multiplatform** with modules `shared` (common logic), `androidApp`, `iosApp` and a `native/` C++ core (CMake). Use KMP-ready libraries in `shared`: kotlinx.coroutines, kotlinx.serialization, kotlinx-datetime, Room (KMP) for the scan database, DataStore (KMP) for settings, Okio for files.
- Android UI: Kotlin, Jetpack Compose, Material 3 (no dynamic colour — the app has its own palette). Use the theme files in `design/android/theme/` as the starting point, adjusting the package name.
- iOS UI: decided later (SwiftUI or Compose Multiplatform — see `07-multiplatform.md`). Phase 0 only needs a minimal SwiftUI shell that calls into `shared`.
- Navigation Compose with the routes listed in `docs/02-user-flow.md`.
- ARCore (`com.google.ar:core`) with the Depth API (raw depth + confidence). Camera feed and 3D overlays rendered with OpenGL ES in a `GLSurfaceView` embedded in Compose via `AndroidView`; all 2D overlays (banners, rings legend, controls) are Compose on top.
- Reconstruction in a shared C++ core (`native/`) for speed and portability: TSDF fusion of depth frames inside the user's bounding box, marching cubes, cleanup. Expose a plain C API (`extern "C"` header). Android calls it via the NDK + JNI; iOS via a static library / XCFramework imported into Kotlin/Native with cinterop. Both sit behind one `MeshEngine` interface in `shared` (expect/actual).
- 3D viewer: Filament (or SceneView, which wraps it) with an orbit camera and shaded / wireframe modes.
- Room for scan metadata; mesh files, keyframes and thumbnails in app-specific storage.
- WorkManager (expedited / foreground) for High detail processing, with a progress notification and a "ready" notification.
- **No `INTERNET` permission.** ARCore installs/updates through `ArCoreApk` and the Play Store.

## Architecture rules

- Unidirectional state. Screen state and presentation logic (ViewModels, `UiState`) live in `shared/commonMain` so both apps reuse them; the scan screen is driven by a `ScanSession` state machine in `shared`.
- The **coverage model**, **guidance engine** and **ScanTuning** (see `04-scan-experience.md`) live in `shared/commonMain`: no Android or Apple imports, fully unit-tested in `commonTest`, fed by a small `FrameMetrics` struct (pose, speed, distance, tracking state, light estimate, depth confidence) that each platform's AR layer fills from ARCore / ARKit.
- Exporters (binary STL in millimetres, 3MF with `unit="millimeter"`) live in `shared/commonMain` and are unit-tested by round-tripping small meshes. 3MF is a ZIP: use a small common-Kotlin ZIP writer (stored entries are valid) or expect/actual.
- Platform-specific pieces go behind interfaces in `shared` with `androidMain` / `iosMain` implementations: `MeshEngine`, `HapticsPlayer`, `StorageInfo`, `FileExporter` (save/share), `DeviceCapabilities` (depth support), `BackgroundProcessor`.
- Keep `commonMain` free of platform types; if something can't be shared, say so and put it behind an interface rather than duplicating logic.
- Units are millimetres internally. Inches are display-only.
- All user-facing text comes from `strings.xml` (start from `design/android/res/values/strings.xml`).

## Phases — stop after each one so I can test on the phone

0. **Project setup (multiplatform).** Create the KMP project with `shared`, `androidApp`, `iosApp` and `native/` as described in `07-multiplatform.md`. Android: theme, fonts (Inter Tight + JetBrains Mono in `res/font`, both OFL), navigation graph with every screen as a stub, strings. Shared: package structure, the empty interfaces listed above, one sample unit test in `commonTest`, and the C++ core compiled for Android with a trivial function called through `MeshEngine`. iOS: an XcodeGen `project.yml`, a minimal SwiftUI app that shows a string from `shared` (proves the framework link), and a `make ios` / script that builds it with `xcodebuild` for the Simulator. If Xcode isn't installed yet, set iOS up but skip the build and tell me. Add `.gitignore` (Gradle, Xcode, generated `.xcodeproj`, build outputs). Create `DEV_TODO.md` listing future export formats (OBJ, PLY, GLB, USDZ) and add `DEV_TODO.md` to `.gitignore` so it stays out of GitHub.
1. **App shell with fake data.** Onboarding (3 pages), camera permission, device check (ARCore availability + Depth support + install/update), unsupported device, gallery (empty and filled, search, filters), scan actions sheet, settings (Light / Dark / Follow system, persisted with DataStore), viewer UI with a bundled sample mesh, export sheet UI.
2. **AR placement.** ARCore session, horizontal plane detection with the dotted surface overlay, tap to place the 3D box, drag handles (top = height, sides = width/depth, bottom = move), Fit to object, scan type (Full object / One side), Start scan.
3. **Capture.** Live TSDF fusion inside the box with a coarse live mesh overlay, coverage rings + mini dial, guidance engine with one message at a time and haptics, pause / resume, interruption recovery, sharp-keyframe saving for High detail, Finish with the incomplete-coverage warning.
4. **Quick result.** Final mesh from the live volume, cleanup (largest component, remove table plane, optional watertight fill, smoothing level from Settings), viewer with real meshes, W × D × H in mm.
5. **Export & gallery persistence.** STL / 3MF writers, file name, Save (MediaStore Downloads/Facet) and Share (Android sharesheet with a `FileProvider`), Room-backed gallery with search, filters, rename, delete, export again.
6. **Scale check.** Manual two-point measurement on the mesh with a typed real length; automatic coin detection near the object (see `04-scan-experience.md`); apply uniform scale and record "scale verified".
7. **High detail.** Background processing from the saved keyframes at a finer resolution, staged progress, notify-and-leave, failure screen with retry / use Quick, low-storage check before starting.
8. **Polish (Android).** TalkBack labels, 200% font scale, reduced-motion, contrast checks, haptics setting, performance and thermal testing on the S24 Ultra plus one mid-range ARCore Depth phone.
9. **iOS.** Before starting, recommend SwiftUI vs Compose Multiplatform for the iOS UI with trade-offs, and wait for my decision. Then: ARKit world tracking + plane detection + scene depth (LiDAR iPhones first; decide with me whether non-LiDAR iPhones are supported), feeding the same `FrameMetrics`, `ScanSession` and `MeshEngine`; Core Haptics patterns matching `Haptics.kt`; 3D viewer (RealityKit / SceneKit or Filament); background processing with `BGProcessingTask` / a background task plus local notifications; Save to Files and the share sheet; theme generated from `tokens.json`; VoiceOver and Dynamic Type pass.

## Non-negotiables

- One guidance message at a time, by priority, with its own icon and vibration pattern. Never use colour as the only signal.
- Camera / AR screens are always dark; the rest of the app follows the theme setting (default: follow system).
- Touch targets ≥ 48 dp in the app and ≥ 60 dp on the scanning screen; primary scan controls sit in the bottom thumb zone.
- Nothing leaves the phone except files the user explicitly saves or shares.
- Values marked "placeholder" in the docs are tunables: put them in one `ScanTuning` object in `shared` so we can adjust them after testing and both platforms use the same values.
- Every phase keeps `./gradlew :shared:allTests` (or the equivalent) green and the Android app building; from Phase 0 on, keep the iOS shell building too.
