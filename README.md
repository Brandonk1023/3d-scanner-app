# Facet (placeholder name)

Phone 3D scanner for 3D printing and CAD. Accurate, true-to-scale meshes, processed entirely on the
phone — nothing is uploaded. Android first (ARCore Depth API), iPhone next from the same repo.
v1 exports STL and 3MF.

- Design handoff and specs: [`design/`](design/) (start with `design/docs/01-product-spec.md`)
- Project structure: [`design/docs/07-multiplatform.md`](design/docs/07-multiplatform.md)

**Status:** Phases 4 (Quick result), 5 (export and gallery persistence) and the manual half of 6
(scale check: tap two points on the mesh, type the real length, apply a uniform scale) are done.
Coin auto-detection for the scale check still needs real keyframes from the phone. On Finish,
the final mesh is cleaned up in the C++ core (table removed and the base rebuilt flat, largest piece
kept, Taubin smoothing from Settings, holes filled for a watertight mesh), then repaired, decimated
and saved. Phase 3 capture and the cleanup values in `ScanTuning.Cleanup` still need on-device
tuning. Debug builds have Settings › Developer › Add sample scans and Simulate a scan (synthetic
depth through the real fusion and cleanup) for testing on the emulator.

## Layout

| Path | What |
|---|---|
| `shared/` | Kotlin Multiplatform: scan logic, `ScanTuning`, `MeshEngine` / `ScanPipeline`, exporters, data, ViewModels, platform interfaces |
| `shared/src/commonMain/.../data/` | Gallery: Room database (`db/`), `RoomScanRepository` (records in Room, each scan's meshes and keyframes in `files/scans/<id>/`), `MeshFiles` (the on-disk mesh format) |
| `shared/schemas/` | Room's exported schema per database version (committed, for future migrations) |
| `native/` | C++ reconstruction core with a plain C API (`include/facet_mesh.h`, `include/facet_pipeline.h`), no Android or Apple dependencies |
| `native/src/` | TSDF fusion and silhouette carving (`tsdf.*`), C API, and `pipeline/` — one file per third-party library (Manifold, meshoptimizer, lib3mf, PoissonRecon) plus our own final-mesh cleanup (`cleanup.cpp`), STL writer and depth → point-cloud code |
| `native/fusion/` | Marching cubes ported from Open3D (keeps Open3D's MIT notice and a "Modified" note) |
| `native/cmake/` | `FacetFetch.cmake` (pinned dependency checkout) and `Lib3mfLibzip.cmake` (cross-compiles lib3mf's bundled libzip headers) |
| `native/compat/` | Empty `<sys/timeb.h>` for Android, needed by PoissonRecon's headers |
| `native/tests/` | Host C++ tests (fusion, carving, every pipeline stage on a synthetic sphere, cleanup of a cylinder fused on a table) |
| `native/scripts/scan_notices.py`, `native/third_party_notices.txt` | Notice scanner and its reviewed baseline (see [Licenses](#licenses-and-credits)) |
| `native/android/` | Gradle module `:nativeAndroid`: NDK/CMake build of the core + JNI bridge |
| `androidApp/` | Jetpack Compose app, ARCore, theme from `design/android/theme`; license texts in `src/main/assets/licenses/` |
| `iosApp/` | SwiftUI shell; `project.yml` is the XcodeGen spec (the `.xcodeproj` is generated). The C++ core is linked through Kotlin/Native cinterop |

## Build

Requirements: Android Studio (SDK 37, NDK 30.0.16248370, CMake 4.1.2 from the SDK manager), Xcode,
`brew install xcodegen`, `git` and `python3`.

```sh
make android    # debug APK
make install    # install on the connected phone
make test       # shared tests (Android JVM + iOS Simulator) + C++ core tests + license-notice scan
make ios        # generate the Xcode project and build for the iOS Simulator
./gradlew :androidApp:verifyNativeLicenses   # also runs automatically before every Android build
```

The first build needs network access once: CMake checks out each pinned C++ dependency into
`native/.deps/` (git-ignored) and reuses it for every Android ABI, iOS target and host build.

## Licenses and credits

Facet's own source code does not have a license yet. The app shows everything below in
**Settings › About**:

- **Open-source licences** — Google's screen, generated by `oss-licenses-plugin` from the Gradle
  dependencies (release builds; debug builds show a placeholder).
- **Native libraries** — our screen with the full text of every license in
  `androidApp/src/main/assets/licenses/`: the C++ libraries, fonts and model, plus full texts for
  the licences that Google's screen only links to.
- The ARCore disclosure and the meshoptimizer credit line.

Each C++ license file is the project's own `LICENSE` at the pinned commit, followed word for word by
the notices of any code it vendors from other authors. Two checks keep this complete:
`verifyNativeLicenses` fails the Android build if a library in `native/CMakeLists.txt` has no license
file or isn't on the Native libraries screen, and `make test` runs `scan_notices.py`, which fails on
any copyright or license notice in compiled third-party code that isn't in the reviewed baseline.

### Adding or updating a dependency

1. Pin it to a commit in `native/CMakeLists.txt` (`facet_fetch`), or add it to `gradle/libs.versions.toml`.
2. For C++ code: copy its `LICENSE` to `androidApp/src/main/assets/licenses/<name>.txt` and list it in
   `androidApp/src/main/kotlin/app/facet/android/ui/settings/NativeLibraries.kt`.
3. Run `make test`. If `scan_notices.py` reports new notices, credit them in the license file, then run
   `python3 native/scripts/scan_notices.py native/build-host --update`.

Do not add OpenMVS (AGPL-3.0), CGAL, Meshroom/AliceVision, COLMAP, or CUDA/PyTorch code.
